런 결과 화면 — 현재 vs 제안

런이 끝난 뒤 「무엇을 벌었나」를 어디서, 언제 읽게 할지 고르기 위한 비교본이다. 왼쪽은 코드가 지금 그리는 것, 오른쪽은 플랜 §2 의 안 ⓐ·ⓑ·ⓒ 중 하나다. 두 화면은 같은 시계로 돈다 — 아래 막대를 끌거나 「재생」을 누르면 런 종료 순간(t=0)부터 같이 움직인다.

토스트가 아니라 패널이다

런이 끝난 같은 프레임에 메인 메뉴로 넘어가고, 그 위에 딤 + 480px 결과 패널(4구역)이 바로 뜬다. Run.cs:517-518 · MainMenuOverlayViews.cs:24. 안내문 「런 정산이 완료되었습니다…」는 메인 메뉴에서 아무도 그리지 않는다(MainMenuView.cs:249-251).

패널 아래, 메뉴 본체에만

베일(α 0.55 · 18px 슬라이드)은 메인 메뉴 _content 에만 걸리고 오버레이는 흔들리지 않는다 (MainMenuView.cs:657-671). 즉 패널 위로 베일이 겹치지 않는다. 겹치는 건 배경이 런 → 메뉴로 한 프레임에 바뀌는 것이다.

      결과 패널 — 실제 크기

      현재·ⓐ·ⓑ 는 같은 패널을 쓴다(바뀌는 건 뒤에 깔린 화면과 뜨는 시점뿐). 구조·문자열·색은 ResultOverlayView 그대로이고, 예시 표시가 붙은 줄은 서식만 코드이고 양은 지어낸 값이다. 나머지 숫자는 로컬 텔레메트리 실측(런 #1 → #2).

      • ① 머리 — 「런 결과」(검은고딕 24) + 신기록일 때만 NEW BEST · 최고 N 알약. 기준은 클리어 수 하나(:626-631).
      • ② 기록 — 처리한 리소스(30px, 카운트업) · 직전 런 대비 · 피버 이월 · 런 목표. 목표 달성 줄만 골드(:633-682). 예: 직전 클리어 17 → 이번 목표 = max(15, ⌈17×1.1⌉) = 19(Run.cs:275-276).
      • ③ 재화 — 4행 [아이콘][이름][획득][정산 후 지갑]. 카운트업은 골드 행만(:683-696). 이어서 「획득한 상자」 최대 6행(:241-248 · :698-707).
      • ④ 행동 — 보물티켓 → 장비로 · 목표 핀 · 「지금 구매 가능 / 다음 노드까지」. 셋 다 없으면 구역째 접힌다(:709-735). 예시의 「조건 분기 (골드 40)」는 skill_tree_nodes_draft.json 실제 노드·기본가.
      • 버튼 — 「확인」(오버레이만 닫음) · 「다시 시작」(StartRun, 포커스 1순위·골드 라벨). 둘 다 열리는 첫 프레임부터 눌린다(:284-305).
      • ⚠ 상자 구역의 캡션 「획득한 상자」는 상자가 0개여도 남는다 — 행만 끄고 구역·구분선은 끄지 않는다(:241-248 · :698-707, ④ 구역의 “고아 구분선 금지” 처리와 다름).

      플랜 서술 vs 코드 — 목업 전에 바로잡을 것

      플랜(또는 조사 문서)이 적은 것코드가 하는 것
      §0·§1 「결과는 메뉴 위에 뜨는 토스트 한 줄」(playtest-findings-2026-09-21.md:18) 4구역 결과 패널(ResultOverlayView)이 _showRunResult = true(Run.cs:518)로 뜬다. 토스트 문자열 _statusMessage 는 메인 메뉴에서 청구자가 없어 안 그려진다(MainMenuView.cs:249-251).
      §0 「0.28초 전환 베일이 결과 토스트 위에 겹친다」 베일은 메뉴 숙주 _content 에만(MainMenuView.cs:660). 패널은 첫 프레임부터 α 1. ⇒ ⓑ(「겹침만 제거」)가 실제로 바꾸는 건 패널이 0.28초 늦게 뜨는 것뿐이다.
      §1 흐름 시작 = 「종료 확인 모달 → EndRun()」 주 경로는 타이머 만료로 모달 없이 EndRun()(Run.cs:606-609). 모달 경로는 「세션 종료 → 종료할게요」 = EndRun(abandoned: true)(RunOverlayView.cs:299-301).
      §4 「중도 포기 0보상 계약(OpenPendingChests(abandoned))」 abandoned 는 상자만 버리고 골드·커밋 등은 정산한다(Run.cs:387-391, :445-448, 주석 :470-474). 정산 0 은 다른 길 — 「일시정지 → 메인 메뉴」가 EnterMainMenu 로 직행(RunOverlayView.cs:257-260)해 결과 자체가 없다.
      T1 「정본 ui-prototype.html 에 런 결과 화면 블록이 없다」 있다 — #result 탭(ui-prototype.html:4551-4571). 다만 옛 3줄 구조(골드 1줄 · 「허브로 돌아가기」)라 현행 4구역 패널과 갈라져 있다. 같은 파일 :2045-2054 는 없어진 GamePhase.Result 를 전제한다(현 enum 은 MainMenu·Settings·Running·Lab, MvpGameController.cs:824-830).

      결정할 것

      1. 어느 안으로 가나 (플랜 T2 ①)

        ⓐ 런 화면에서 정산 먼저 — 추천ⓑ 베일 뒤에 띄움ⓒ HUD 카운트업

        근거: owner 가 이상하다고 한 건 결과를 보는 순간 배경이 메뉴로 바뀌어 있는 것이다. ⓑ 는 코드상 이미 겹침이 없어(MainMenuView.cs:660) 0.28초 지연만 더하고 원인은 그대로 둔다. ⓒ 는 상자·목표·다음 행동을 담을 자리가 없어 결국 메뉴에서 패널을 한 번 더 띄워야 한다. ⓐ 는 패널을 새로 만들지 않는다 — 같은 ResultOverlayView 를 런 필드 위에 세우고, EnterMainMenu(...) 호출(Run.cs:517)을 「확인」 뒤로 옮기는 것이 핵심이다. 정산·저장 순서(:443-520)는 그대로 둔다.

        ⓐ 구현 주의: 지금은 EnterMainMenu 가 필드를 끄고 ClearNodes() 를 하므로, 미루면 그동안 필드를 멈춰 둘 장치가 필요하다(GamePhase 에 Result 가 없다 — 새 값 또는 플래그). 상자 정산이 필드 노드를 읽는 순서(:511-516 주석)는 그대로 지켜진다.

      2. ⓐ 에서 「확인」을 누르면 어디로 가나

        메인 메뉴연구소 개요 — 추천

        근거: owner 가 2026-08-26 에 이미 C-1=(b) 「확인 → 연구소 개요 착지」를 확정했는데, 「EndRun·화면 생명주기 변경」이라 별도 플랜으로 미뤄져 있다(MainMenuOverlayViews.cs:284-286). ⓐ 가 바로 그 생명주기 변경이라 같이 처리하면 EnterMainMenu 한 번을 EnterLab(LabTab.Overview, …) 로 바꾸는 것으로 끝난다. 이번에 한 번 더 확인만 받으면 된다.

      3. 뜨자마자 버튼을 누르는 문제 — 입력 유예와 건너뛰기

        현행 유지(즉시 누를 수 있음)카운트업 0.75초 동안 버튼 잠금 + 클릭 = 즉시 최종값 — 추천잠금만

        근거: 결과 닫기 27회 중 10회가 1.5초 안, 최단 0.20초 — 읽기도 전에 닫혔다. ⓐ 는 클릭 연타 중인 런 필드 위에 패널이 뜨므로 이 문제가 더 커진다. 잠금 시간은 새 상수가 아니라 기존 ResultCountUpDuration(0.75초, :47)를 쓰고, 저모션(_queueLowMotion)은 지금처럼 즉시 최종값이라 잠금도 0이다. 오른쪽 ⓐ 화면에서 버튼이 흐린 구간이 이 안이다.

      4. 결과에 무엇을 적나 (플랜 T2 ②)

        현행 4구역 그대로 — 추천+ 최고 DPS+ 처치 수

        근거: 플랜 후보 중 「처치 수」는 이미 ② 의 큰 숫자(처리한 리소스)이고, 「다음 목표」는 ④ 의 핀·다음 행동 줄이 맡고 있다. 「최고 DPS」는 런 중에 재는 값이 없다 — run_end 가 남기는 필드는 clears·gold·commit·bcoin·arch·feverEnters·maxCombo 뿐이다(Telemetry.cs:103-113). 넣으려면 새 관측 필드가 필요하니 별도 플랜으로 분리하자.

      5. 중도 종료 두 경로를 어떻게 다루나

        「종료할게요」도 같은 결과 단계 · 「일시정지 → 메인 메뉴」는 결과 없음(현행) — 추천둘 다 결과 단계

        근거: 두 길은 정산 여부가 다르고(Run.cs:470-474), 주석이 「섞지 말 것」이라고 못박고 있다. 대신 「종료할게요」 때 상자가 0개면 「획득한 상자」 캡션만 덩그러니 남으므로 상자 0개면 구역째 접기를 같이 하자(④ 구역과 같은 규칙, 신규 색·문구 0).

      정본 html/ui-prototype.html 은 이 비교본 때문에 바뀌지 않았다. 안이 정해지면 정본의 #result 탭을 현행 4구역 + 채택안으로 갱신한다(플랜 T3 전).
