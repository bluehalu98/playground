3. G4 — StageMaxHeight 상향? 597 포화선이 실효 상한이다

드로어화로 stageBand 는 692 → 942 로 늘지만, 실제 스테이지 높이는 StageMaxHeight 가 정한다. 그리고 스테이지를 키워도 상자는 597 에서 멈춘다(StageBoxMaxSize = 430, 430 / 0.72 = 597).

G4(b) 유지 500 — 스테이지 Δ = 0

편익은 "하단 정리"뿐이다 — 리빌 연출은 1px 도 커지지 않는다. owner 가 이걸 알고 고르는지가 G4 의 요점(승인서 F-1).

G4(a) 상향 — 실효 범위 500 < h ≤ 597

597 이 실효 상한이다. 그 이상 값을 넣으면 상자·리빌은 그대로고 스테이지 빈 판만 커진다 (승인서 R2-2). 597 을 넘겨 키우려면 StageBoxMaxSize(430)를 같이 올려야 하는데 그건 연출 크기 변경이라 별도 육안 승인 항목이다.

4. G5 — 열림 시 스테이지: (a) 오버레이 vs (b) 폭 축소

판정선은 신화 광선의 가로 최대 도달이다 — popScale 1.70(UI.cs:2883) → gemSize = 360×0.5×1.70 = 306 → rayOuter = 306×(1.45+0.18) ≈ 499(GemDrawView.cs:1086-1087) → 중심 936 기준 x ≈ 1435 승인서 R3-1 실측. 광선은 showElapsed 내내 그려진다.

G5(a) 오버레이 — 재배치 0, 가장 쌈

재배치 비용 0 — 스테이지·CTA·RevealFx 를 전혀 건드리지 않고 z-순서와 마스크 경계만 판정하면 된다. 대신 드로어가 열려 있는 동안 레전더리·신화 광선의 바깥 끝이 가린다. 이 가림은 G1=(c)(i)(리빌 종료 직후 열림) 조합에서만 0 이다 — §5 참조 승인서 R3-1.
G4=(a) 597 을 같이 고르면 도달선이 x≈1532 로 밀려 가림이 562안 222px · 452안 112px 로 커진다 파생.

G5(b) 폭 축소 — 가림 0, 재배치 유상

가림 0이고 G1 어느 조합에서도 안전하다. 대가는 재배치 6개 (_stageRoot · _stageLocalRect · _stepLabel · 무지개 밴드 · CTA · RevealFx._stage). 단 승인서 R3 실측대로 실비용은 무지개 밴드 6장 재배치 + _stage readonly 해제뿐이다 — 링(h≥274 면 260 캡)·파티클(앞항 ≤150 지배)은 폭 1310~1872 구간에서 시각 결과가 불변이라 RevealFx 통째 재생성(≈162 Image)은 불필요하다.
