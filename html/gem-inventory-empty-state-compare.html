5. 이 플랜이 건드리지 않는 것

격자선 — 도입하지 않는다 (OQ2 = (a))

위는 목업 정본의 격자 규칙(armament-menu.html:344-348 — 컨테이너 border-top/left + inset -1px -1px 로 4변을 닫는다). Canvas 에는 이 선이 없다 — 채운 상태 SyncTiles 도 타일만 놓는다. 빈 상태에만 격자를 넣으면 비대칭이라, 격자 파리티는 mockup-parity-sweep-plan 소관으로 넘긴다.

밴드 위치·구조 — 무접촉 (하드 제약 5)

밴드의 배치 rect·계층은 손대지 않는다. 뽑기 탭 인벤토리를 하단 밴드 → 우측 드로어로 옮기는 것은 형제 플랜 gem-draw-inventory-side-drawer-plan 소관이고, 이 플랜이 선행한다 — 빈 상태 로직은 GemInventoryBand 클래스에 붙어 있어 드로어가 밴드를 옮겨도 그대로 따라간다.

본 구현은 GemInventoryBand 한 곳 수정이고, 소켓 탭 (SocketsView.cs:482, true,true)과 뽑기 탭 (GemDrawView.cs:248, false,false)이 같은 클래스 한 벌을 공유하므로 두 탭에 동시에 걸린다.

이 페이지는 정적 비교본이다 — 실제 렌더는 Unity Canvas 판이 정본이고, 빈 상태 실측 캡처(T1, 격리 세이브 키)는 아직 남아 있다(에디터 미가동). T1 결과가 "프레임 정상 표시"로 나오면 §1 인용부의 결함 서술은 "IMGUI 한정·소멸"로 확정되고, 남는 산출물은 이 페이지가 보여 주는 T2 배치 · T3 문구다.
