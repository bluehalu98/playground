2026-09-06 갱신 — 좌우를 걷어내고 상하로 몰았다 (fever-edge-flames-updown-plan, owner 지시 "버닝 때 좌우에 너무 직사각형으로 이펙트가 나오는데 차라리 상하에 나오는 불꽃이 나오게 해줘").
fever_band 는 위가 불투명 → 아래로 소멸하는 세로 경사다. 상(0°)·하(180°)는 불투명면이 화면 바깥을 향해 정상이지만, 좌우로 눕히면 하드 컷선이 화면 안쪽(x=132 / x=1788)에 서서 "직사각형 띠"로 읽혔다. 그래서 좌우 밴드 2장 + 좌우 핫 림 2장을 제거하고, 남은 Image 예산을 상하 혓바닥(14 → 18열)으로 옮겼다. §B 가 그 결과, §C 가 현행과의 병렬 비교다.
회전 부호 각주(해소됨): 플랜 §1 은 이 문서의 좌 +90°/우 −90° 가 코드의 좌 −90°/우 +90° 와 부호가 반대라고 기록했다. 실제로는 좌표 손잡이(handedness) 차이다 — CSS rotate() 는 y-down 화면에서 시계방향, Unity Euler z 는 y-up Canvas 에서 반시계방향이라 같은 그림을 만들려면 부호가 반대여야 한다. 즉 둘은 화면상 같은 결과였고, 둘 다 하드 컷을 안쪽에 세우고 있었다(RunFxView.cs "각 면이 화면 바깥쪽을 위로" 주석 쪽이 틀렸던 것). 좌우 밴드를 지운 지금 이 불일치는 소멸한다 — 남은 회전은 상 0° / 하 180° 뿐이고 두 표기가 부호와 무관하게 일치한다.

C. 비교 — 현행(4면) vs 상하 강화(좌우 제거)

owner 눈 확인용 병렬 도해. 같은 산식·같은 상수로 그린다(아래 buildStage() 하나가 둘 다 그린다). 왼쪽의 붉은 점선이 좌우 밴드의 안쪽 하드 컷선 (x=132 / x=1788)이고, 그 바깥 세로 흰 선이 핫 이너 림 3px 이다 — 밴드만 지우고 림을 남기면 이 세로 직사각형이 그대로 잔존한다.

현행(4면) — 밴드 4 · 혓바닥 14열(진폭 0.50 · 폭비 0.60) · 엠버 4면 순환 · 림 4.
문제 ① 좌우 밴드의 불투명 하드 컷이 화면 안쪽에 서서 세로 직사각형으로 읽힌다.
문제 ② 상단 혓바닥은 localScale=(1,−1,1) 이 CanvasUi.Place 의 pivot(0,1) 강제와 충돌해 rect 가 y<0 으로 반사된다 — 도해에서 흐리게 칠한 부분이 그것으로, 실제 화면에서는 안 보인다(코드 수준 재현 확정 · 런타임 실측은 owner 몫).
상하 강화(좌우 제거) — 밴드 2 · 혓바닥 18열(진폭 0.62 · 폭비 0.66) · 엠버 상하 2면 순환 · 림 2.
해소 ① 좌우에 요소가 0 이라 안쪽 하드 컷선이 생길 자리가 없다.
해소 ② 상단 혓바닥은 배치 y 를 높이만큼 내려 pivot 반사를 상쇄한다 (Place(x, topHeight, w, topHeight)) — 미러는 유지되고 rect 는 [0, topHeight] 에 앉는다.
